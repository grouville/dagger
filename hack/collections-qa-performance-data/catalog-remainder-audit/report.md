Three concrete leads, in priority order:

1. **Reduce cold SDK filesystem hydration, starting with the bundled cache seed's usefulness.** `.dagger/modules/engine-dev/build/sdk.go:211` packages a Go toolchain, module cache and build cache after precaching with `xx-go`; `core/sdk/go_sdk.go:685` imports the full image, reads the two seed directories and mounts ordinary cache volumes over them. `core/builtincontainer.go:57` first copies the OCI chain into persistent content storage, then `engine/snapshots/pull.go:262` applies every layer. The next bounded diagnostic should identify the slow layer by its verified bundled manifest/config, record its byte/file count, and count actual compiler cache hits for the two module builds. If substantial seed bytes are never used because package/toolchain/build inputs differ, make that seed smaller or correct its build inputs in release packaging. This removes both unused extraction and repeated compilation; it complements static metadata because actual Go function execution will still need compilation. The observed4.196s apply union and14.572s build union bound affected regions, not predicted gains. Contract gates: same toolchain/platform/CGO behavior, actual checks/codegen, cold offline dependency availability, first-call versus edit compilation, layer digest/rootfs equivalence where claiming repackaging only. Do not delete cache seed blindly or force SDK flags to manufacture cache hits.

2. **Avoid a guaranteed redundant builtin-content byte copy while preserving ordinary snapshot/cache ownership.** `builtinContainerInto` calls `contentutil.CopyChain` from the engine-shipped immutable OCI store to the session engine's persistent store before any apply. The provider adapter in `internal/buildkit/util/contentutil/copy.go` exposes buffered ReadAt reads; this is a full byte copy even though both resources are local and immutable. A content-store-native verified local clone/copy-on-write fast path with the current streaming fallback is a narrow experiment, independent of schema/SDK behavior. The measured0.592s copy union is the upper affected interval here, not a command saving. Required proof: destination digest verification, fresh lease attachment before publication, crash/partial-copy cleanup, ENOSPC/cancellation, no mutation of shipped content, export/restart/GC behavior and cross-filesystem fallback. A global read-through store that bypasses the current content lease/GC contract is not proposed. First inspect provider/store capabilities; do not add Linux reflink assumptions to the generic interface merely for a benchmark.

3. **Remove duplicate registration parsing using a pass-owned metadata snapshot.** Current production's self-type names and object-directive retention parse the same files independently around runSource. The design in `registration-snapshot-design.md` combines those two metadata passes while keeping inference, directive evaluation, diagnostics and namespace authority unchanged. Consequently the narrow production patch needs its own matched production-dependency measurement. A later parse-once declaration API could remove the remaining pass in38711, but inferred AST/environment caching is explicitly out of scope.
