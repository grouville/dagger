The original managed-start prototype has one source-confirmed correctness blocker: Docker's `.State.Running` includes paused containers. In pinned Docker v28.5.2, daemon/start.go checks `Paused` before `Running` and returns a conflict telling the caller to unpause. Skipping start on a paused container would discard that existing error and proceed into connection waiting. Running and Restarting can also both be true, as documented by container/state.go.

Use the same single inspect operation with `{{.State.Status}}` and skip ContainerStart only for exact trimmed `running`. Preserve the existing start path for `paused`, `restarting`, stopped and unknown states, and preserve missing-container creation behavior. Update the protocol tests accordingly. daemon/inspect.go obtains Status from StateString, which distinguishes paused/restarting before ordinary running.

Apart from that correction, the optional backend capability is narrowly scoped: existing Docker inspection supplies the needed state; other backends keep existence-plus-start, unknown/error paths keep current handling, and cleanup still excludes the active engine. The command-protocol test checks a real subprocess invocation rather than only a helper. A stopped engine still starts normally. The observation remains point-in-time; neither this path nor the existing start call guarantees the process stays alive afterward. Subsequent connection checks remain authoritative. No Unix socket selection, permissions, image-loader behavior or global liveness cache is introduced.

This is an independent source review only. No tests, Docker calls or source edits were performed for it. Approval is conditional on replacing the boolean test and validating paused/restarting fallback.
