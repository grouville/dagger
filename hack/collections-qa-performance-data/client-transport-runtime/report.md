The normal-path unit witness confirms one API/telemetry connection instead of two and two warmed connector tunnels instead of three. This runtime matrix did not independently count physical Docker execs. It validates the actual command path and full cleanup latency; it does not establish that every environment will maintain one HTTP/2 connection. A low peer stream limit can still require another connection.

The earlier unchanged-source witnesses fail on the expected connection/topology counts. The pre-correction owner witness fails because Close could return before a pending dial/physical close completed. The corrected focused normal and race suites pass, including API cancellation after headers, late final telemetry records, slow streams, reconnects, partial initialization and joined concurrent Close.

Warm native calls improved in all three pairs (median 308.5 → 278.2 ms), while warm generation worsened in all three (256.9 → 290.9 ms). This is sufficient to keep the candidate isolated pending phase attribution, rather than repeat a large matrix without a mechanism. The next useful diagnostic would separate API work, telemetry drain and owned physical-close timing for warm generation, and compare those with the same phases for native API calls.

Generation file-visible timing is separate from full exit. Warm generation already has the correct generated bytes and therefore has no fabricated "time to new file" value. Unique edit generation and export poll for the exact expected bytes every 5 ms; both the observed visibility time and remaining exit tail are in the numeric evidence.
