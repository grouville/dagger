## Current work that must not be duplicated

Verified `eunomie` = Yves Brissaud. Sources and exact PR head pins are in `findings.md` beside this review.

- [Go SDK #36](https://github.com/dagger/go-sdk/pull/36) (Solomon) and [Java SDK #19](https://github.com/dagger/java-sdk/pull/19) (Yves): static Dang type entrypoints, runtime builds behind `call`. Adopt/test that contract instead of adding another schema format or universal source scanner.
- [Go SDK #35](https://github.com/dagger/go-sdk/pull/35) (Yves): build-only optional runtime. No runtime codegen is a different property from no compilation for metadata.
- [Python SDK #33](https://github.com/dagger/python-sdk/pull/33) (Yves): unified clients with shared or generated static entrypoint. The current shared `types()` explicitly runs `python -m dagger.mod describe` through the installed module. Shared entrypoint support alone does not eliminate Python startup.
- [Dagger #14299](https://github.com/dagger/dagger/pull/14299) (Yves): client-target and pinned Git-commit inputs fix invalidation. Preserve these dependencies; new clients must not make stale results win. Its PR explicitly says large client-fan-out costs remain unmeasured.
- [Dagger #14346](https://github.com/dagger/dagger/pull/14346) (Yves): serve local clients from their owning module tree. Includes a per-call host snapshot; benchmark it on larger workspaces rather than assuming it is a performance optimization.

No matching open Dang directive-retention PR was found, and upstream Dang main still lacks retention. The proposed six-line library fix plus deletion of the engine's reparsing workaround is therefore independent useful work. It has passing focused tests and an original-library negative control; a full command benchmark and Dagger collection integration checks are still pending.
