The measured stack already coalesces fresh Git admissions within each session. Adding another generic singleflight or batching cache would duplicate existing behavior; no new implementation is justified by these profiles.

Both retained fully primed profiles contain 16 executed `Query.git` calls but only seven successful `git.publicAdvertisement` operations, zero `git.lsRemote` operations, and seven reused HTTP connections. Advertisement unions are 385.63 ms and 384.95 ms. All seven operations in each profile have distinct opaque nearest `Query.git` identities, share one query root, and descend from module-source loading. There are zero open operations, dropped events or Git errors. These are overlapping diagnostic intervals, not removable command latency.

The profile deliberately stores opaque call identities rather than URLs. It cannot directly name the repositories or detect two textual aliases of the same server resource. The source establishes the stronger useful boundary: `cachedPublicRemote` keys its in-flight and completed entry by session ID plus `remote.Remote()` (core/schema/git.go:1253–1296). The fragment is removed, so different refs/subdirectories do not require another admission (util/gitutil/url.go:58). Different client IDs in the same session share the entry. `GetOrInitArbitrary` joins ongoing initializers as well as completed results (dagql/cache_arbitrary.go:101–129). This code is byte-identical in the measured 0d stack and current branch.

Module-source resolution constructs `Query.git` from clone URL and optional commit, with no service binding (core/modulerefs.go:163–187). Thus, assuming the normal live engine cache shown by that path, seven successful advertisements are consistent with seven distinct session/remote keys rather than repeated probes of the same key. This is source-backed inference, not decoded URL evidence. The normal probe also primes the existing session-owned ref metadata cache; authenticated/service-bound entries are excluded, and the caller receives an independent decoded copy (core/git_remote.go:66–144). No second refs fetch was observed.

The existing `TestPublicRemoteAdvertisement` already witnesses 16 concurrent clients → one anonymous GET, no later metadata GET, copy isolation, a deliberately separate service-bound probe, and a new session observing a repository becoming private. This audit read those tests; it did not rerun them. Service-bound requests must retain their separate visibility scope. Host/path aliases cannot be collapsed generically: routing, case sensitivity and repository access may differ even if a particular host redirects them to the same place. A ref pin also does not replace anonymous admission.

A repository-specific HTTP discovery endpoint cannot combine independent repository access decisions just by collecting the calls in another local batch. Scheduling known, already-selected dependencies earlier could overlap waiting, but it does not eliminate any of these seven requests. Previous source/dependency audits and the bounded pipeline experiment already cover that distinction; do not eagerly probe unused lock entries or extend the session freshness window. The next queued experiment remains the current-production registration parse snapshot, which removes repeated local work and has a validated ownership boundary.
