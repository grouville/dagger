Public PR status and head snapshots were refreshed on 2026-09-26; none of the following PRs was merged or imported as part of this refresh. PR descriptions can describe older development limits, so the current repository source remains authoritative for supported engine contracts.

- [Go SDK #36](https://github.com/dagger/go-sdk/pull/36) and [Java SDK #19](https://github.com/dagger/java-sdk/pull/19) remain open prototypes for generated entrypoints and dispatch. This is the existing route for removing registration processes, including compilation needed only to obtain types. Our scheduling prototype does not introduce a competing schema format.
- [Python SDK #33](https://github.com/dagger/python-sdk/pull/33) remains open and depends on engine client-tree/cache correctness work. A Dang entrypoint alone is not proof that runtime type discovery has disappeared; the selected entrypoint mode still matters.
- [Engine #14299](https://github.com/dagger/dagger/pull/14299) tracks declared local clients in call identity and adds git commit identity. Its description explicitly leaves large client fan-out costs unmeasured. This reinforces holding broad evaluated-prefix caches: repeated dynamic-input work cannot be suppressed solely because a call looks syntactically identical. Re-run edit/invalidation checks after integration.
- [Engine #14346](https://github.com/dagger/dagger/pull/14346) resolves a module's local clients from its own tree. It documents a host-tree snapshot on each host-module call. The direct ancestor-metadata optimization can reduce setup for such reads without dropping source contents; it does not eliminate their required traversal. This cost belongs in later large-repository benchmarks.
- [Remote-cache verification #14241](https://github.com/dagger/dagger/pull/14241) remains open and covers the persistence/transfer/acquisition/sharing series. Remote hits can avoid producer work when usable cached values exist. That does not itself remove local Docker subprocesses, session admission, or the fresh anonymous Git visibility requests measured here. This is an architectural inference, not a benchmark of that PR.

The reviewed transport/startup and private path-helper changes preserve those freshness and authority boundaries. The scheduler prototype changes concurrency only and retains the final publication barrier; that is still a resource/performance experiment, not evidence of compatibility with every future SDK/cache head. No guarantee follows from matching file lists alone.
