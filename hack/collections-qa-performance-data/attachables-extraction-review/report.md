# Independent source review: attachables extraction

One compile blocker was found before validation: the moved filesync code references `InstrumentationLibrary`, whose definition remains in `engine/client/tracing.go`. The new package must define the same `dagger.io/engine.client` constant, preserving existing span/log scope without importing its parent client package. The implementing agent was notified. This review's hashes preserve the original source state; a later correction needs its own hash/check.

Otherwise the source boundary is coherent. Byte comparisons confirm the complete filesync and socket implementations differ only in package declaration, and the entire upgrade/server block is unchanged. The initializer diff is only its aliased import and gofmt ordering. The moved private filesync tests are identical after package renaming.

The old package keeps aliases for all moved exported concrete/interface types and forwarding constructors/server factories. These aliases retain exported Go method sets, struct fields, assignments and call signatures. Reflection reports the new defining package, and old-package code loses access to the moved types' unexported members. No remaining production use of those private members was found in the old package. This is source API compatibility, not a promise about reflected names, precompiled plugin ABI or stack function names.

The transport/provider bodies preserve the HTTP upgrade request, existing metadata and propagation, service-method advertisement, 101 response validation, one-byte ACK, health service, caller contexts, error wrapping and connection/server cleanup. Existing client lifetime code still owns the same Run call through an alias. The initializer's FD3 readiness close, subprocess handshake, credential/header construction and provider order are unchanged. This move does not fix pre-existing cleanup behavior or add retries, caching or authorization.

The source graph removes provisioning driver/image-loader registrations from the session helper. `mainSession` does not select/provision an engine or load a host image, so those registration side effects have no identified consumer there. Its actual advertised secret, Git, h2c, socket and filesync providers remain directly imported; their protocol/propagation dependencies remain. This is a bounded source argument, not proof that every removed transitive initializer is irrelevant under every application.

The static graph result is 373 removed packages and one added package, net 1,228→856. It establishes dependency reachability only. It does not establish startup latency, memory savings, compiled correctness or full API compatibility. No runtime or compiler was invoked for this review.

After fixing the missing constant, useful gates are the copied filesync/search/parent-metadata tests, existing real attachables upgrade/lifetime tests, an external-package alias/constructor compile witness, and focused race tests. Search matters because it is the moved path that uses the instrumentation constant. Then compare matched helper binaries before choosing a real SDK smoke; keep this ordinary single-binary extraction separate from the held split-PID1 mount design.
