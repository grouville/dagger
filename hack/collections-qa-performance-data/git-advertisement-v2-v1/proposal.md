Historical preflight proposal. The sole v1 execution later stopped after two primer requests; see live-v1-report.md and live-v1.json. The preflight statements below describe what had been run before that execution.

Prepared and locally validated experiment; no remote request executed: compare the existing anonymous Git v0 discovery response with an anonymous v2 capability response. This tests whether avoiding reference enumeration changes observed HTTP response waiting; it does not change Dagger admission, cache policy or Git behavior.

The frozen profile evidence justifies measuring this particular mechanism. Seven anonymous advertisements occupy approximately 385 ms of overlapping wall time in the earlier fully primed listing profile; all seven reuse connections, and reference decode/validation is only a few milliseconds in total. The wave experiment did not turn its much earlier ninth source into a comparable catalog gain. A smaller response is useful only if it reduces request latency, not merely parser time. Write-to-first-byte combines network latency, routing, queueing and remote work; it must not be labeled server time.

Use the seven distinct public repository names already present in the greetings lockfile: dagger/eslint, dagger/go, dagger/go-sdk, dagger/node, dagger/playwright, dagger/sdk-helpers and dagger/typescript-sdk. The source lockfile hash is recorded in targets.json. The targets are HTTPS GitHub repository info/refs resources, not vanity URLs. The count matches the retained profile, but this experiment does not infer a profile operation’s identity from its duration or ordinal.

The exact request budget is 24 HTTP GETs, run sequentially through one persistent TLS HTTP/1.1 socket: two counted connection primers against dagger/go (one without Git-Protocol, one with Git-Protocol: version=2), then one v0/v2 pair for all seven targets with alternating pair order, followed by one reverse-order pair for four prespecified targets (dagger/go, dagger/go-sdk, dagger/sdk-helpers and dagger/typescript-sdk). This gives two pairs for those four and one pair for the remaining three. Every request, including primers and unsuccessful responses, consumes the budget. No retries, redirect following, auth challenge retry, ls-refs POST, object fetch, Cloud export or Git credential-helper invocation. A redirect is a classified result and a reason to revisit a canonical target before a separate trial, not permission to follow a new destination.

Both modes use the same Go runtime, explicit HTTP/1.1 transport and go-git User-Agent/Accept values; only Git-Protocol differs. HTTP/1.1 is explicitly selected through ALPN, and Accept-Encoding: identity is identical in both arms. The implementation uses net/http request writing/response parsing on a single TLS socket rather than http.Client/Transport, avoiding their automatic idempotent-GET retries. There is no reconnect, proxy, cookie jar, URL userinfo or Authorization path. The launch environment is sanitized. Report the host-process/network-path scope; this cannot establish whole-Dagger-command savings or parity with an engine configured with a network proxy. Keep TLS verification enabled. Do not add cache-busting parameters or Cache-Control changes. The two primers are excluded from latency comparisons but retained in all accounting. Record whether each timed request actually reused the connection rather than assuming reuse.

Bounds: 15-second request deadline, 180-second experiment deadline, at most 16 MiB per response and 64 MiB in aggregate. Stop without retry or reconnection on any failed request, server connection close, deadline, oversized response, unexpected destination or HTTP 429/5xx. A response is fully consumed to EOF and closed before the next request whenever it is within the cap. Oversized bodies are closed and end the experiment instead of being drained indefinitely. No simultaneous whole-CLI timing or other network benchmark.

Measure request start to completed body read, initial DNS/TCP/TLS setup, request write to first observed application response byte, that byte to body EOF, and separate local parse/validation time. There is no connection-pool wait because one established socket is used sequentially; this is not an engine HTTP/2 comparison. Record only fixed classifications, numeric counters/timings, ordinal/public repository mapping and the requested/negotiated protocol. The first-byte observer wraps the connection read below the response parser and is reset after each completed write. It is not a timestamp taken after parsing headers. This measures observation by the application, not packet arrival at the host. Retain no body, refs, SHA list, auth headers, cookies or arbitrary error text. In-memory response parsing is necessary, but response contents are not evidence artifacts.

Require HTTP 200 and Git upload-pack advertisement MIME type before protocol validation. Use the existing pinned go-git v0 decoder plus AllReferences for v0; classify empty repositories distinctly rather than treating them as populated. For v2, require a complete bounded pkt-line capability advertisement, version 2, a supported upload-pack command capability, a terminal flush and no trailing malformed data. A v2 response supplies no HEAD, ref, peeled-tag or commit-existence proof. If a server ignores the v2 request header and returns a valid v0 response, parse that same body and classify it as v0 fallback; do not issue a second request. HTML, truncated packets, unexpected content types, 401, 403 and 404 remain separate outcomes; this mechanistic driver never converts any of them into a Dagger public/private decision.

Before live requests, a local httptest gate should prove request/header parity, absence of credentials/cookies, redirect refusal, response-size and request-count bounds, EOF consumption/reuse, valid v0 fallback, complete v2 framing, malformed/HTML/empty/auth cases and cancellation. All six focused local test groups passed normally and with the race detector, then the standalone binary compiled. See validation.json and manifest.json for the exact source/build pins. No remote request has run.

Report per-target raw paired latencies and protocol/status/byte counts. Two pairs for four targets and one pair for three cannot establish stable p95 or a general speedup; do not pool seven repositories as repeated samples of one population. The reverse-order subset checks gross warming/order effects only. Reused transport removes connection establishment as the intended confound; CDN/server caching and repository-specific behavior remain. If v2 saves bytes but response wait stays flat, stop this line of work rather than implementing a second protocol path for parser savings below the measured critical cost.

The experiment cannot prove authorization compatibility from public repositories alone. Native Git http-backend performs repository/export/service checks before advertising either protocol, and the official HTTP protocol requires access control at that resource. Hosting gateways could differ. Before any engine implementation, validate native public/private/export-disabled fixtures and a deliberately generic capability gateway, retain fresh per-session anonymous admission and credential isolation, and make the host-admission contract explicit.

Current consumer boundaries are already suitable for a later narrow design, if evidence warrants it: core/schema/git.go cachedPublicRemote remains keyed by session plus canonical remote (service-bound requests bypass sharing); publicRemoteProbe separates public from optional metadata; PrimePublicRemote refuses nil metadata, credentials and service bindings; RemoteGitRepository.Remote performs a session-owned full metadata lookup when demanded. Only a truly locked full-SHA operation that needs no refs can avoid full enumeration. Named refs, unpinned latest, HEAD, tags and release-tag consumers still need metadata; a v2-first strategy may add an entire exchange for them. Do not invent ref data or seed a persistent public-visibility cache. No production source change is part of this experiment.

Official sources previously reviewed: https://git-scm.com/docs/gitprotocol-v2, https://git-scm.com/docs/gitprotocol-http, and Git v2.55.0 http-backend.c/serve.c/ls-refs.c.
