The v2-request response was HTTP 200, 191 bytes and failed this harness’s parser. Its body was intentionally not retained, so the actual reason cannot be reconstructed or labeled a server protocol failure. Both calls were primers; no timed comparison phase ran and no speedup is inferred. Cloud requests: zero.

The parser assumed a bare, LF-terminated version packet. Source review after the failure found two compatibility gaps: Git’s HTTP client strips an optional service banner before version detection, and the common pkt-line specification requires equivalent handling of text with or without a trailing LF. Native http-backend normally omits the service banner for v2. These are source-backed parser corrections, not evidence of which framing this particular discarded response contained.
