# CLI exit-tail diagnostic

Diagnostic-only overlays prepared from commit `341595f37647998908de840dd6350f981628c715`. Shared source, module versions and engine binaries are unchanged. Existing cli-boundaries work supplied the instrumentation approach, but those old sources and experimental HTTP/1 or compression changes are not reused.

Build: `python3 /tmp/collections-perf/cli-exit-tail-v2/build.py`. The script builds unchanged current HEAD and the diagnostic overlay using `CGO_ENABLED=0 GOMAXPROCS=4 go build -mod=readonly -buildvcs=true`, with a temporary `build.mod` and no version ldflag override. Exact commands, exit codes and resulting binary hashes are in `build-results.json`; each overridden repository/dependency file is hashed in `source-manifest.json`. `overlay.json` additionally maps a new helper file into the already pinned otel-go module and instruments its existing provider shutdown calls. Go 1.26 rejects overlays beneath GOMODCACHE. Both binaries therefore use the same temporary modfile replacing otel-go with a byte-verified copy of the already pinned version under this directory. `pinned-dependency-files.json` records every copied file hash. There is no dependency upgrade or shared go.mod change. The rejected direct-module-cache attempt is retained separately.

For one already-authorized invocation, set `DAGGER_PERF_EXIT_TIMELINE` to an absolute fresh JSONL path and use `dagger-diagnostic` with the same arguments, environment, workspace, stdout expectations and retained engine as the unchanged CLI. The parent owns invocation scheduling and Cloud command approval accounting. This directory contains no driver that makes Cloud calls automatically.

The first JSONL row is `{kind:"anchor",unix_ns:<UTC UnixNano>,start_ns:0,end_ns:0}`. Subsequent rows use static `kind`, monotonic-relative `start_ns`/`end_ns`, and optional `values` containing only fixed-name numeric counters. Rows are written on CLI exit, so file order follows completion/append order; sort by start_ns for a timeline. The UTC anchor aligns to external process timing without wall-clock arithmetic within measured phases. No raw URL, host, port, token, header, trace/span/session/writer identifier, payload, error text or user argument is emitted. Transport attempt addresses are used transiently only to pair concurrent ConnectStart/ConnectDone hooks; they never enter a row or output file.

Phase kinds:

- `cli.main`, `cli.execute`, `cli.pre_run`, `cli.labels`: whole Main/Cobra command boundaries and label initialization.
- `cli.with_engine_frontend`: withEngine/withSetupSessions including frontend teardown; `cli.command`: the actual callback between connection and cleanup.
- `engine.connect`, `engine.close`, `engine.shutdown_http`, `engine.subscribers_drain`, `engine.close_lock`, `engine.clients_cleanup`, `engine.subscribers_final_drain`: existing client shutdown sequence. clients_cleanup measures waiting for the already-launched client-close group, not a sum of each parallel closer.
- `cli.stdio_close`, `cli.root_end`, `cli.telemetry_close`: the terminal root events after the engine client has closed.
- `otel.provider.traces`, `otel.provider.logs`, `otel.provider.metrics`: existing sequential signal-provider shutdown calls, preserving their shared timeout, order, returned errors and logging.
- `analytics.finalize`, `oauth.finalize`: Cobra finalizers outside the main telemetry shutdown.
- `cloud.export.traces`, `cloud.export.logs`: actual exporter calls with record counts. Export serialization/retries/body decoding are included in these spans; only transport calls have the detailed HTTP hooks.

HTTP rows use static kinds `cloud.traces`, `cloud.logs`, `cloud.metrics`, `cloud.other`, `analytics.http`, `engine.shutdown_request`. start_ns/end_ns cover the request through response body Close. Inside `values`, get_conn_ns/got_conn_ns/wrote_request_ns/first_byte_ns/response_headers_ns are offsets from that request's start. connection_acquire_ns is GetConn→GotConn, which includes DNS, dialing and TLS for a new connection; it is NOT pure queue time. connect_ns sums matched dial attempts and can exceed elapsed wall time if attempts overlap. dns_window_ns and tls_window_ns are first-start to last-done windows, with attempt/error counts. Request write delay after acquiring the connection is wrote_request_ns−got_conn_ns; response wait is first_byte_ns−wrote_request_ns when both exist. These intervals may include HTTP/2 stream admission/flow control; they do not independently attribute server CPU or a processor's queue.

`request_content_length` reports the existing request's declared length (−1 means unknown). `response_bytes` counts only bytes the original caller reads. The wrapper never reads, clones, hashes, drains, decompresses or logs a body itself; normal body reads and Close retain their original n/errors. `status`, connection reuse/idle flags, write/transport/read/close error counts and response EOF/Close flags are numeric. HTTP hooks compose with existing traces. The original transport, pooling, HTTP/2, authentication, exporter sequence metadata, timeouts and retries remain intact.

Observers only collect bounded records in memory during the command (maximum 10,000). JSON/file work happens at Main exit and has its own `diagnostic.flush` row; external process wall includes that final observer cost. The final flush row's duration covers earlier serialization/writes, not its own final write or descriptor Close. A zero dropped_events counter is required before treating the diagnostic complete. Any response the application never closes may lack an HTTP row; the aggregate surrounding close/export phases still delimit work. Early argument/workdir failures that call os.Exit before exitWithCode is established do not flush diagnostics.

CLI-only observations can identify whether the tail is chiefly engine.shutdown_http, client stream drain, or the CLI's later provider shutdown. They cannot describe the engine's own Cloud HTTP requests, because the retained engine is unchanged. Instrument the engine only if this first split makes that necessary. Parent and child phase durations overlap; never add them as independent costs or call the residual an optimization saving.
