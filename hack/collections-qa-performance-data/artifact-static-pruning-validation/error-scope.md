# Scoped metadata validation: source audit and concrete witness

The full candidate is retained for review. Narrow discovery already scopes ordinary module loading: `filterPendingWorkspaceModulesBySelectorInclude` explicitly selects known requested modules and falls back to all for unknown prefixes, while `workspaceTargetModules` passes those includes through overlay/value-workspace loading. A newly selected workspace therefore does not validate every unrelated module. Already-served modules were nevertheless all rebuilt by `collectArtifacts`. The candidate makes this static traversal scope consistent with targeted fresh loading, while retaining all entrypoints and broad/pattern fallback.

There is a real late-error difference, not just a hypothetical one. An empty named Module can be served because `userMod.install` has no definitions to install and returns success. `NewModTree` then rejects it with `no main object` before schema construction. The added test performs both real operations and checks the prefilter plus actual ModuleArtifactNodes: selecting that module, an unfiltered catalog, an entrypoint, a pattern, or an unknown prefix still yields its error. Selecting a different known literal module skips the unrelated tree. This documents intentional error scoping rather than promising identical unrelated-error behavior.

Other NewModTree errors include constructing the module schema and obtaining dependency TypeDefs. ArtifactNodes can also fail on collection validation or batch metadata construction. CollectionMembers validation ordinarily already runs in Module.validateObjectTypeDef while definitions are finalized, so an arbitrary malformed collection is not a reliable example of a served late error. The empty module witness does not rely on bypassing that validation.

SDK NewArtifactTree is different: its value is the engine-owned WorkspaceSDK object. It obtains DefaultDeps (currently core), reads the core TypeDefs and builds a name map. It does not parse or validate the custom SDK's authored schema. `workspaceSchema.sdks` and workspaceSDKResults still run for the complete inventory before pruning, preserving configuration, source/ref and scope construction errors. A bad custom SDK module can have ordinary module loading/tree errors, but it is not newly validated inside this engine-owned SDK tree builder. Core metadata/context failures remain possible; the candidate does not claim cancellation/error ordering equivalence for work that is intentionally not requested.

The original measured 38-command and four-command follow-up source/binaries remain unchanged. This new test snapshot adds only the error-scope witness. Its normal and race gates both passed, with26 test/subtest entries in each; exact outcomes are retained in validation.json. No additional runtime matrix is required solely for this test.
