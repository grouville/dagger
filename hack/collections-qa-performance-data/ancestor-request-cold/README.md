# Prepared fresh-volume parent-metadata comparison

This driver is prepared for review only. Root schedules execution after the shared-transport benchmark. Four commands total, all local-only: `dagger check -l --all` on a new baseline volume, its identical warm repeat, the same first call on a new candidate volume, then its warm repeat. Exactly 14 expected output rows must match byte-for-byte on every command.

Both containers and empty named volumes are created by this run with random names, a dedicated owner label, recorded immutable container IDs and volume creation timestamps. The pinned existing engine image, frozen v1 Linux binaries and SDK blobs are copied into both containers before timing. No image build or explicit image pull occurs. Normal engine resolution during the first CLI may fetch uncached module/image dependencies. The CLI starts with an allowlisted environment, empty private XDG config, tracking disabled and no Cloud/OTLP/cache-export configuration. No existing engine is restarted or overwritten.

Engine start to debug readiness is separate from CLI time. Each CLI timer uses blocking waitpid through full exit. Setup, hashing and numeric snapshots are outside it. Snapshots retain engine I/O and CPU, host pressure, dirty/writeback bytes and whole-host diskstats. Host counters include unrelated work and do not prove causation. Cumulative engine writes have a sampled 8 GiB guard; free disk has a 16 GiB floor. A 300 s command timeout sends SIGINT then bounded SIGKILL only to the spawned process group. These sampled guards are not storage quotas; stop-time writeback may follow the final cgroup sample.

Only exact newly created resources are stopped and removed after evidence. Output/profile data and any engine errors stay private. Source fixture hashes must be unchanged at the end. Raw stdout/stderr is not a shareable artifact. Binary/source pins, numeric timings/counters, exact-output hashes and cleanup status can be exported separately.

This is one ordered pair, not an ABBA distribution: baseline always comes first and may warm host pages or upstream services for the candidate. The Docker image and SDK blobs already exist, the public fixture's generated sources are retained, and host page/image caches are not cleared. Report each raw cold and warm value, startup separately, and any host pressure difference. It cannot establish a general cold-start gain or explain earlier variability by itself. Linux v2 production behavior is identical to these measured v1 binaries; the later portability correction only accepts the protocol slash on Windows.
