# Explicit Go base Address: correctness proof

Nine local CLI calls passed on one frozen engine; this is a correctness gate, not a performance comparison. Both greetings-api arms used the same workspace-relative Go module layout. The only module/config difference was the explicit optional `baseAddress` input instead of eager `base`. Both produced the same ordered 14 checks and passed the strict real HTTP check (missing service URL is fatal).

The retained-session witness passed ten RPCs. Two direct Address consumptions invoked a successful NEVER producer twice and yielded distinct generations. Repeated access through one retained, default-cached GoModule.base returned the same container. This is the ordinary outer-cache contract: a nested NEVER call does not make every cached wrapper transitively NEVER. Both container consumptions reached the bound HTTP service and returned the expected generation/marker; an actual GoModule.test also passed.

Fresh CLI invocations independently proved the user edit loop. The original test passed; changing the service marker produced the expected single-check failure; inserting a fatal assertion after the actual HTTP check produced the expected real-source failure; restoring the test and editing both source and service markers recovered successfully. The Go test embeds the source marker, so recovery checks source contents against the configured base and bound service. No cache was cleared and no new broad NEVER policy was introduced.

All authored fixtures were restored. The original greetings copy, stopped engine binary, and init binary were unchanged; the retained volume was preserved, and the newly owned engine container was removed. The nine-call proof wrote 82,325,504 engine cgroup bytes. Cloud was disabled using an empty configuration and an allowlisted environment. The local with-session telemetry proxy was permitted only at validated loopback HTTP endpoints; this Python probe emits no OTLP.

Three earlier recorded harness trials stopped at their first failing query. Trial v2 declared an obsolete WorkspaceID scalar; unchanged diagnostic v3 captured the validation error privately. Trial v4 corrected all scalars to ID but still used obsolete load<Type>FromID fields. The final probe uses universal ID and node(id:) with typed inline fragments, matching the current generated SDK. Keys was valid throughout. All seven final query shapes passed the GraphQL parser; core field/argument contracts were checked against a previously generated actual production schema. No module schema was fabricated. Failed raw responses remain private; only fixed validation messages and numeric cleanup evidence are included here.
