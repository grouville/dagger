# Explicit ancestor request: portability correction and extraction audit

A final source review found that fsutil.Send always asks its filesystem to Walk the protocol root `/`, including on Windows. The measured v1 helper accepted only the host's native separator. Windows would reject the request before sending metadata. The v2 production correction accepts literal `/` as well as the native separator; this changes no Linux behavior. The measured v1 Linux binaries, dependency pins, command data and profiles remain frozen and were not rebuilt or silently relabeled.

Nine focused groups pass normally and under the race detector with v2, including the actual DiffCopy wire-dispatch tests, legacy JSON fallback, invalid-request rejection, freshness and first-divergence missing-target witness. The new protocol-root test accepts both wire and native roots and rejects subtree walk targets. The Windows/amd64 fsutil test binary cross-compiles successfully. This proves build compatibility, not Windows execution or drive/UNC/reparse integration.

These gates used the frozen `ancestor-request-v1/builds/engine.mod` dependency pins with the v2 test overlay, rather than the ordinary checkout's go.mod. Exact commands, environment, source hashes and outcome logs are retained in validation/results.json. No engine or Cloud command was involved.

The source audit confirmed all six production files and three test files in the shared worktree match the extracted v2 sources byte-for-byte at audit time. The production extraction consists only of the additive request flag, strict request validation, fresh directory-chain source, client dispatch, engine opt-in wiring, and the fixed-label parent-sync wcprof marker. It excludes every historical f864 SDK/Dang/schema/telemetry overlay and every dependency change used to make the controlled benchmark stack.

An independent review then caught a second issue confined to the test oracle: fsutil normalizes Windows modes (adds execute bits and masks 0755), so raw os.Stat mode is not the expected transmitted mode. The separately prepared v3 test correction compares with fsutil.Stat's normalized value. Changed mtime remains the cross-platform freshness witness. Production v2 source and its race proof remain unchanged. The final v3 test-only gate passed all nine normal groups using ordinary checkout dependencies; no claim is made that the initial v2 test executed successfully on Windows.

Path review: test targets convert slash-separated examples through filepath.FromSlash; emitted packet names use filepath.ToSlash; volume roots derive from the actual temporary path. Invalid mixed-mode cases fail before root traversal. Helper tests comparing callback paths use a single native-independent component or normalize them. Symlink fixtures require host support/privilege, as existing fsutil tests do. Native Windows integration remains a CI validation item; Linux source/micro/runtime evidence does not substitute for it.

Final production v2 and test v3 were committed as `0d1c32e29f`. All nine committed files match the tested final source hashes. The 54-command confirmation also completed two real mixed-version compatibility calls: baseline engine with candidate CLI, then candidate engine with baseline CLI. Both returned the exact expected 14 rows. These are separate from the original wire-unit proof; no further compatibility calls are needed. Runtime binaries still carry their frozen 85b60f source/version provenance.
