# Workspace.findRoots names-only lead

`descendantRoots` in `core/schema/workspace.go` builds an imported directory with `Include: **/<marker>` and caller excludes, then calls `Directory.glob` once per marker. Its answer uses only matching paths. Importing marker contents, computing content hashes, applying a mirror and making an immutable snapshot is unnecessary for that answer in principle.

This is now a low-priority lead: the runtime owner reports seven findRoots calls totaling about 20 ms inclusive after the ancestor fix, with only three descendant imports totaling about 8.6 ms. Those overlap other work and are not predicted full-command savings. The older saved profile in this audit had seven executions totaling 49.954 ms; it predates the explicit-parent change and must not be used as the current ceiling.

A direct substitution with `Workspace.glob` is not presently equivalent. `directoryAt` uses `resolveReadRootfs`: path resolution, selected workspace owner, filtered host import, overlays, mounts and non-host trees participate. `Workspace.glob` performs a fresh host glob and separately merges overlay/mount matches. In addition, its host implementation starts filepath.WalkDir directly, whereas `fsutil.NewFS` used by directory import resolves the starting symlink and requires a directory. Caller excludes can prune descendants; applying exclusions only to the final match list would still visit inaccessible/pruned subtrees and produce different errors. Directory matches carry trailing slashes, marker arguments are basenames but may contain glob metacharacters, and ancestor-before-descendant/marker ordering and dedup must remain unchanged.

A narrow host-only fast path would need all of: a local host workspace, no overlay or mounts, empty excludes, equivalent root resolution/missing-directory errors, and matching glob semantics. Even that requires tests for a symlink start, a marker-shaped directory, metacharacter basenames, workspace cwd, missing start, inaccessible branches, and fresh host edits. Do not infer host-read authority from HostPath alone; use the existing workspace-owner context while retaining the caller's execution scope.

The more coherent eventual design is an explicit filtered-names host request using the same fsutil filter semantics, including pruning, with no file opens or snapshot. Select it through negotiated capability or preserve a deliberate older-client fallback. It should return relative matched names from a fresh walk; no persistent host index or TTL is needed. For mixed/in-engine workspace views, keep existing tree handling until a separately tested names merge has identical overlay removal and mount-shadowing semantics. Ancestor lookup remains separate and must still choose the closest strict ancestor.

Retained PR reviews cover remote-cache verification, module client keying/local source ownership, and static SDK registration. None of their saved scopes describes removal of marker-content imports. This is a retained-scope comparison, not a claim about current upstream PR heads. No implementation is proposed this round because the remaining local critical-path ceiling is small.
