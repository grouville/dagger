The current workspace lock does not provide a selected dependency graph, so pre-probing all seven locked repositories is not a justified generic optimization. No source was changed and no new repository request or cached parent-content read was performed for this audit.

`util/lockfile/lockfile.go:35` stores tuples of namespace, operation, inputs and a string result. The standard operations in `core/workspace/lock.go:19` are Git ref/SHA, OCI and vanity-URL lookups; none records a parent-to-dependency edge. The fixture also retains historical refs and image versions. A pin says which result to use if requested, not that its repository is needed by the current command.

The workspace config explicitly selects nine modules for the all-artifacts catalog. Six remote module entries collapse to five distinct Git repositories, because two entries use different modules/refs within dagger/go. The remaining node and sdk-helpers repositories occur in the lock but are not selected top-level roots. The three local module manifests declare builtin Go/TypeScript runtimes and local backend/frontend dependencies. This is insufficient to infer remote child reachability without an admitted parent manifest. A narrower selected check can demand still fewer roots; `ensureModulesLoadedModeWithSuccess` applies that filter before batch resolution (`engine/server/session_workspaces.go:1197`).

The present source ordering already exposes children early once that authority exists. `gitModuleSource` resolves the Git repository/ref before reading its config (`core/schema/modulesource.go:762`). `loadConfiguredModuleSource:1177` reads and validates the config, then starts every declared dependency concurrently. The context/SDK branch runs in parallel with those dependencies; only SDK loading follows source-context materialization. `ResolveDepToSource` preserves relative-source context and marks only declared remote dependencies/SDK refs as trusted resolution (`core/modulesource.go:2143,2323`). External SDK loading resolves its source before its asModule registration (`core/sdk/loader.go:93`). Reading a persisted parent manifest before its current session admission would bypass the ordering this audit must preserve.

The measured bound remains modest for the permissible local reordering already identified: source-context before SDK was only about 6–8 ms in the retained profiles. The root pipeline experiment moved the final top-level source approximately147 ms earlier but changed the diagnostic catalog by only24 ms, leaving seven advertisements and four catalog runtime processes. The older advertisement union was approximately385 ms; the pipeline baseline’s newer profile was310.5 ms. These are separate observations, neither an additive saving nor a promise from earlier admission.

One bounded possibility remains: begin anonymous admission for already selected, validated canonical remote roots before their expensive registrations occupy the batch slots. It must use the identical per-session cached probe, actual HTTPS transport identity, existing service-binding bypass, and no credential lookup. It cannot derive arbitrary targets from the entire lock. This does not remove the nested dependency waves, and the pipeline result gives weak evidence that advancing the final root is valuable. Rank it below eliminating proven runtime/bootstrap work.

A longer-term declarative graph could contain edges supplied in the workspace lock and bound to each exact parent commit/config path, SDK policy and config digest. It would need explicit reachability and invalidation semantics, not an engine cache of old parent contents. Even then the design must decide whether child admission may precede successful parent admission, and must not contact unused children after a failed parent. That is a format/authority design, not a small safe scheduler patch.

A separate source-only clue deserves attribution rather than assumption: `ResolveDaggerGetRedirect` probes any eligible schemeless/HTTPS source without a positive vanity lock mapping; it caches negative results only within the session (`core/modulerefs_redirect.go:46,186,213`). Several retained profiles have68–78 ms between source start and the first Git operation, but there is no dedicated vanity timer proving that this HTTP probe accounts for the gap. A persistent identity routing pin might remove repeat negative routing work while retaining fresh repository admission, but it would change redirect-refresh semantics and needs an explicit design. Do not turn this unmeasured clue into a savings claim or skip hosts by hardcoded name.
