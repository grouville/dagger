The ordered plan alternates variant order between successive pairs, beginning baseline then candidate for the single cold pair. One cold pair is a proof of behavior, not a distribution of cold-start latency. Both engines use independent fresh Dagger volumes but share host caches and identical supplied SDK blobs. Engine provision and startup are recorded separately. No host cache flush is performed.

The intended optimization defers expensive module-facing TypeDef materialization until it is requested. It does not delete required module metadata work. The first core version command or native generation primer may pay that deferred cost; both have explicit timings, CPU/allocation/GC counters and summary rows. First greetings artifact discovery occurs later and cannot establish a cold artifact-listing win. Moving work into a request may also change which internal operations are visible to telemetry; the two ordinary binaries remain uninstrumented.

Every CLI timer uses a fresh `Popen` through a dedicated thread's blocking `waitpid` completion. The parent waits on an event, avoiding `Popen.wait(timeout)` polling latency. Generation readiness is separately polled every 5 ms, with censoring when process exit wins the polling race. Setup, snapshots, correctness checks and one-second inter-command pacing lie outside the timer. Cgroup/MemStats/host PSI deltas bracket a slightly wider interval and may include background work; they do not identify a specific causal phase.

The driver records attempted commands before launch, applies a 300-second per-command bound with owned-process cleanup, checks a 16-GiB free-disk floor and an 8-GiB cumulative engine-write guard, and stops its own engines in `finally`. It keeps volumes for evidence. Original native input/output bytes are restored; all other native and greetings files are hash-verified unchanged. Production uses the existing approved normal login; local calls use an empty XDG config without propagated Cloud credentials. The script never reads or prints credential contents. Raw stdout/stderr remain private.

The selected execution is `TestFormatResponse` only, not all six application tests. Native generation exercises a small real Dang `@generate` path, not SDK code generation. Findings should remain scoped accordingly.
