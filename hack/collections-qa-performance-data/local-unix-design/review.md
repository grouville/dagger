A Unix-socket fastpath is feasible, but it should remain inside the existing image/container driver. Preserve runtime selection, provisioning, image loading, sessions and engine cleanup; replace only connector dialing. This audit is source-only, with no implementation or additional measurement.

The raw Unix comparison is a ceiling: besides avoiding exec tunnels, it skips the Docker availability probe (`drivers/docker.go:25`, `dial.go:31`). Its explicit Docker image-store override preserves an otherwise missing attachable: raw `unix://` normally has no image loader (`dial.go:38`), whereas the container driver supplies one (`container.go:173`; registration at `client.go:646`). An automatic connector-only change would still pay existing availability/provisioning costs.

The minimum safe design has these boundaries:

- Keep a managed endpoint descriptor tied to the selected runtime/daemon and full container ID. A filename or mutable container name is insufficient. Both Connector.EngineID methods are empty today; the initial BuildKit handshake verifies the Dagger package, not the selected container (`client/buildkit.go:53`). All connections and any initial fallback must reach the same engine instance.
- For eligible new engines, expose a short socket path through a private directory owned by the calling user. Validate ownership, mode and symlinks rather than repairing unfamiliar paths. The existing listener uses mode 0660 and configured UID/GID; the rootful Linux test's host GID mapping is not proof for rootless/user namespaces (`cmd/engine/main.go:717`, pinned containerd `pkg/sys/socket_unix.go:46`). No TCP exposure or world permissions are needed.
- Eligibility remains real implementation work. Absent DOCKER_HOST, or even a Unix Docker endpoint, does not prove a shared host filesystem/kernel. Desktop, proxies, remote contexts, rootless Docker, Podman/Finch and Apple need explicit capability evidence. Start with verified native Linux Docker; otherwise retain stdio. Do not use `/proc/<pid>/root` as a general user path.
- Reuse existing container inspection for descriptor lookup where possible. Older containers without the mount keep stdio; do not recreate an active engine to accelerate it. Fall back only during connection establishment, never by replaying a failed application request. Keep unavailable-endpoint decisions within the connector, without a cross-session TTL.
- Socket lifetime follows the engine, including restarts and concurrent clients, rather than CLI lifetime. Remove only an exact owned directory after its container was removed. Another user's engine should retain stdio fallback, not broader permissions (`container.go:456`, `docker.go:62`).

Endpoint access is privileged engine access. Main admission permits callers to establish new sessions with their own IDs/secrets; the token protects an existing session, not global engine admission (`server/session.go:1710`, `:1879`). A persistent socket also bypasses future Docker-exec authorization checks. Automatic enablement needs an explicit policy for that authority/revocation difference; session tokens do not make it disappear.

Required proof: extend existing creation/warm-tunnel fake-backend tests for supported/unsupported endpoints, stale descriptors, canceled connection attempts and fallback without request replay. Add two-daemon same-name and replaced-container identity cases, symlink/permissions/rootless rejection, concurrent-client/restart/owned-directory cleanup, and older-engine fallback. Real direct-socket checks must preserve image loading, source edit invalidation, export, services and final telemetry/cancellation. Existing anchors are `container_create_test.go`, `container_connect_test.go`, `session_attachables_lifetime_test.go`, and separately gated backend tests in `container_test.go`.

This changes connection establishment, not module-result caching. Detailed source references and the remaining locality/authority questions are in `source-details.md`.
