The fully primed listing still has two large sequential phases: 651.95 ms in `Workspace.artifacts`, then 800.27 ms in collection expansion. The profiled query union is 1476.03 ms. These are one local diagnostic observation, not ordinary medians or guaranteed removable costs.

The catalog launches four runtime processes below `ModuleSource.asModule`: 97.23, 106.70, 138.94 and 117.61 ms. Their sum is 460.48 ms, their interval union 379.68 ms, and the longest is 138.94 ms. They lie inside the catalog and overlap network and other module loading; none of those aggregates predicts an equal command improvement. Two later processes, 98.69 and 104.31 ms, belong to the authored backend constructor and `GoTestBase` during collection expansion. They are separate from metadata registration.

The strongest work-removal path is therefore the existing static `ModuleEntrypoint.types` contract. `core/schema/modulesource.go:3197` uses `AsModuleTypes` when available; otherwise `moduleDefViaRuntime` at line 3313 builds/loads a runtime and calls its special empty-name registration function. `core/sdk/entrypoint.go:120` supplies the static-entrypoint path while preserving scoped module/source identities. Migrating the remaining fixture SDK/module registration through that contract can remove process startup and, on fresh caches, compilation done solely to obtain metadata. The retained Go SDK #36 and Java SDK #19 proposals already own this direction; Python SDK #33 must be evaluated by selected mode because its shared entrypoint still executes Python to describe types. This report does not claim those retained PR heads are current. Do not introduce a second metadata format or globally cache a bound Module result.

The engine already bypasses an absent constructor in `core/object.go:1220`. The backend in this fixture has an authored constructor and an authored `GoTestBase` that configure source/service bindings. Omitting those processes by observing a small method body would change the execution contract. The earlier broad deferred-default prototype remains held: declared input freezing alone does not freeze ambient workspace reads or authority. Static metadata does not remove these two authored calls.

Our complementary immediate candidate is identifying and reducing Git admission work without weakening freshness. Seven `git.publicAdvertisement` operations occupy 330.99 ms of interval union in this profile. The current implementation already shares one anonymous probe per remote/session and primes its refs for subsequent metadata reads. A pinned commit identifies content, not authorization for a new session. `core/schema/git.go:1253` retains service-bound exceptions and session boundaries. There is no evidence of duplicated fresh-ref lookup to delete and no evidence of a new TLS connection per probe.

The prepared diagnostic-only overlay adds fixed-label timers around connection acquisition, DNS/connect/TLS, request-write to first response byte, the last first-byte boundary through advertisement decoding, `AllReferences` validation, and ref materialization/sorting. It preserves the transport and cache. The post-first-byte interval includes headers/body transfer and decoding, so it must not be called server time or pure parsing time. A first-byte-before-write callback is marked ambiguous and suppresses subsequent derived write intervals rather than mispairing retries. Only observed outcomes should determine whether a smaller visibility response, reduced local validation/materialization, or scheduling is worthwhile. A protocol-v2/selective-ref redesign is not yet justified, and reuse of the full advertisement must remain available to existing consumers.

A second scheduling opportunity is real in source but remains unmeasured. `loadConfiguredModuleSource` at `core/schema/modulesource.go:1176` loads the source context and then its SDK serially in one job, while dependencies are resolved in parallel. The same diagnostic build adds two fixed spans to measure this sequence without reordering it. Starting SDK resolution on an immutable, already-authorized source description could overlap it with fresh context import, but SDK entrypoints/local SDK resolution may read parent context. The future patch must explicitly define which SDK loader paths can run before context completion, use a detached input rather than race on `ModuleSource`, join errors/cancellation deterministically, and preserve all source/default-path identities. Host.directory union is only 36.73 ms now; network advertisement union is not an SDK/context overlap estimate.

Pipelining catalog and expansion has a larger theoretical envelope but is not a small safe optimization yet. `collectArtifacts` at `core/schema/artifacts.go:632` waits for every selected module before constructing trees. `engine/server/session_workspaces.go:1254` resolves a bounded parallel batch, then performs deterministic failures, source deduplication and ambient-entrypoint arbitration before installation. Expansion also depends on catalog-wide path/flag/dimension validation. Starting arbitrary constructor calls as soon as one module is ready could run authored work for a request that ultimately fails validation. A correct design would need an explicit expanded-listing plan, an authority-safe dependency closure per ready module, bounded work, deterministic final errors/results, and no externally visible partial output. It cannot turn the existing static listing/help command into eager evaluation. First measure module readiness and the Go/backend dependency closure; `min(651.95,800.27)` is only a loose structural overlap envelope, not a supported saving.

Repeated schema preparation is not the next demonstrated large target. The observed session.schemaBuild markers total 27.27 ms over 248 calls, and eleven schema.forkPrepared calls total 3.42 ms. These markers do not cover every possible standalone schema construction, so they do not prove all schema work is cheap. They do show that another broad per-session cache proposal cannot be justified by merely counting 248 requests. Existing scope-bound prepared-schema reuse must retain authority/session/ancestor client identity and input-default semantics.
