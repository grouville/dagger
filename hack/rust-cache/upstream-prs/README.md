# Performance changes prepared for review

Sixteen branches are pushed to [grouville/dagger](https://github.com/grouville/dagger). The first fifteen are independent: ten are based directly on main `717589c9cc`, and five on main `ff0b029a4d`. The sixteenth builds on the scalar-field policy branch. No pull requests have been opened for these proposals. Each description is ready for individual approval and includes the measurements, validation and tradeoffs.

The first six rows and the tenth cite component benchmarks. Their gains cannot be added together or treated as seconds saved on a complete Rust build. The seventh also measures allocations during complete listings; the eighth and ninth establish complete listing speedups. The tenth establishes a full Go listing improvement in the larger follow-up; earlier small Rust command results remain mixed. The array cases have one input path per returned string. The collection index is rebuilt for every measured call; there is no persistent warm index. The usage-map case measures preparation for disk pruning, with fixture construction outside the timer.

The usage-map change also has a [retained-cache comparison](../REAL_CACHE_USAGE.md): 59,192 real engine results, two eight-pair series, 563 → 538 ms and 567 → 530 ms for size measurement and prune-state preparation together. All pairs allocate less, with identical result counts and accounted bytes. This remains an accounting measurement; complete Rust-command savings are not established.

The measured tradeoffs support submitting these changes for review. The collection index needs the closest algorithm review because it replaces ancestor selection. The scalar-array changes need review of type eligibility, persisted compatibility and resource ownership. The first twelve introduce no new lock; declaration reuse adds a bounded shared cache and keeps parsing outside its mutex. Complete Rust-module comparisons use the diagnostic engine, with the individual candidate controlled separately; the isolated upstream heads are tested directly on their recorded main bases. Component and complete-command measurements remain separate.

## Measurement and validation

The first five comparisons use six fresh-process A/B and B/A pairs, with the same test sources on both sides. The baseline restores only the production files to main. Go 1.26.6, linux/amd64, Intel Core i5-9300H, `GOMAXPROCS=8`; 150 ms per case, except the 200,000-result usage snapshot, measured once per process. Builds and race tests completed before measurements began. Maximum recorded host pressure was about 4.2% CPU, 1.7% I/O and 0.1% memory during samples.

The three dagql branches each pass the full `./dagql` race suite. The CLI and collection branches pass focused unit suites with the race detector; the exact commands are in their descriptions. New compatibility tests pass on both arms. The CLI burst test fails on main because rows are lost, and passes on the branch in all three formats. Closed-pipe tests pass on both arms.

The sixth proposal uses a separate six-pair comparison on real temporary snapshot stores, with initialization and fixture insertion outside the timer. It improves both the zero- and 1,000-snapshot cases in all pairs. Seventeen focused server tests pass normally and under the race detector; the new regression fails on main in both scheduled and explicit pruning. Its [raw evidence](../experiments/snapshot-gc/) records host pressure over complete processes, including fixture construction, and retains initial harness failures. It establishes no complete Rust-command saving.

The seventh proposal uses six fresh-process pairs on real spill files and a complete `engine/clientdb` race run. Its ownership test passes on main and the candidate, and rejects a decoder deliberately changed to borrow the frame. Two eight-pair edited-command cohorts establish 108 MB fewer allocated bytes per large listing in 15/16 pairs, with mixed latency. All six retained native Rust histories remain fully reusable. Its [dedicated evidence](../experiments/telemetry-spill-batch-buffers/) includes pressure, initial admission failure, profiles and the separate unselected Protobuf screen.

The eighth uses two eight-pair complete-command cohorts, six fresh-process component pairs and focused artifact/schema race tests. Both getters are still read and their parent objects still load by ID. Profiles verify exactly 6,156 fewer listing publications, while edited checks execute neither changed getter. Separate check-only and identical-policy controls retain an apparent timing difference and uneven Go-GC counts; no compilation gain is claimed. All six native histories retain their artifacts. Its [evidence](../experiments/artifact-dimension-key-fields/) includes the controls, raw profiles, source manifests and initial harness failures.

The ninth uses two independent-order eight-pair full-command cohorts, six experimental and six standalone-main component pairs, focused artifact/core/schema race tests and object-ID compatibility. All six native histories remain reusable. Profiles verify 2,052 fewer publications while both getters and object-array lookups remain present. Its [evidence](../experiments/artifact-metadata-fields/) keeps the rejected object-list ID failure, raw pressure and the checkout performed during confirmation.

The tenth uses six fresh-process component pairs directly on main, with a new index on every iteration, plus two independent component screens with sequential and mixed IDs. The full clientdb race suite passes on the standalone patch; compatibility passes before and after. Three full-command cohorts retain 32 listing pairs: 20/32 are faster, with 119 ms median paired saving and an uncertainty interval including zero. Separate completed profiles demonstrate 88,993,812 skipped ordinary-child comparisons and sampled indexing CPU of 0.58 → 0.11 CPU-second. No compilation gain is established. The [later full Go comparison](../NATIVE_GO_WIDE_TRACE_INDEX.md) improves 53.58 → 46.72 seconds in three successful pairs, with one failed control retained; its index avoids over two billion comparisons per session. Allocation and IO differences are disclosed. The [earlier evidence](../experiments/span-lookup-fanout/) retains all Rust cohorts, pressure, source manifests and six reusable native histories.

[Exact branch and base revisions](branches.json) and [raw benchmark/test evidence](evidence/) are saved alongside the descriptions. Each candidate has `summary.json`, per-process metrics and host pressure in `runs.json`, the raw paired logs, test logs and production-file hashes. `evidence/SHA256SUMS` covers those files. Large binaries are excluded.

The archived benchmark driver regenerates baseline overlays with `git show`. Its configs record the measurement worktree paths; recreate those worktrees at the recorded revisions or adjust their paths before running it. Each description also gives a direct `go test` command.

This batch contains engine, CLI and Go SDK changes. Rust module/cache changes and experimental engine APIs are outside these proposals.

The eleventh proposal batches Go module metadata reads in the generated entrypoint. A transport regression runs the generated dispatcher against the real SDK and checks exact JSON and errors; main fails its request-count assertion. Complete collection commands improve in 10/12 pairs over two cohorts, while the ordinary workspace control is flat. It only benefits regenerated Go entrypoints. Its [evidence](../experiments/go-module-batched-inputs/) records both cohorts, the control, full traces and the current-main test results.

## Additional dependency candidate — still being validated

An [additional draft targets containerd's duplicate GC roots](containerd-root-dedup.md), rather than Dagger itself. The standalone patch and regression apply to containerd main. Complete edited commands during concurrent collection improve in 16/16 pairs, saving about 0.33 seconds per pair. The confirmation also shows a roughly 62 ms slowdown without concurrent collection, and the unique-root control is about 9% slower. These costs remain disclosed and under investigation; this candidate is not included among the sixteen ready proposals. No containerd PR is open.

The [follow-up](../NATIVE_GC_ROOTS_FOLLOWUP.md) attributes the idle discrepancy to preparation rather than an executed command-time loop, and tests a single-lookup alternative. Ordinary edited commands remain about 1.55 s with either mode, versus Cargo's 0.77 s. The refined collector is faster in all eight forced jobs; complete commands improve in six of eight pairs. Both versions remain available for review, with no default switch enabled; this dependency experiment adds no ready Dagger proposal.

The fourteenth proposal uses concrete builtin value types to return stored scalar fields directly. All four complete Go listing pairs improve; the component and repeated-read allocation tradeoff are reported separately. The full DagQL race suite, 32 retention/persistence checks, standalone behavior tests and all six native histories pass. The first name-only prototype fails a resource-owning integer regression and is rejected before installation. [Evidence](../experiments/trivial-scalar-projection/) includes the corrected component harness, diagnostic routing failure, full ordered outputs and all profiles. No PR is open.

The fifteenth proposal uses a fresh compact bit index during class-ID compaction. It improves all twelve symbolic comparisons and all eight populated-cache comparisons; the simpler array regresses the sparse case and is rejected. The boundary regression and full standalone DagQL race suite pass. This is a maintenance measurement: the retained engine is unchanged and complete-command benefit is not established. [Evidence](../experiments/cache-compaction-mapping/) includes all source variants, comparisons, memory tradeoffs and standalone provenance.

The sixteenth proposal removes item cache entries when a list of explicitly declared immutable data is queried only for stored builtin scalars. All four complete Go pairs improve. The full standalone DagQL race suite, 32 top-level retention tests and every new projection check pass; all six native Rust histories remain reusable after restart and the cohort. The native-field regression rejects the incomplete array adapter, proves zero item rows during scalar reads and checks later attached IDs. [Evidence](../experiments/scalar-list-projection/) retains that failed screen, resource probes, controlled and standalone source, both cohorts, full outputs and the validated wcprof preflight. No PR is open.
