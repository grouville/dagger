A conservative suffix check avoids running the glob regexp on paths that cannot match. Complete warm Go test listing after a test-file edit moves **6.93 → 6.69 seconds median**, faster in all four pairs. The change adds 13 production lines to the shared pattern matcher. It preserves the same files, authored getters, selection and execution; no additional cache or dependency is introduced.

The investigation started by profiling the original CLI together with the engine. Complete commands spend about five CPU-seconds in the CLI. Four current diagnostic captures put roughly 0.4 sampled CPU-seconds in regexp matching, much of it under host globs. Earlier engine-only captures could not attribute that work. Those initial captures preserve 804 module evaluations after test edits and three after ordinary-source edits, with the expected discovery reuse.

The compiled regexp remains the authority for possible matches. For an eligible pattern such as **/*.go, the matcher records its literal ASCII ending and rejects paths without that ending before entering the regexp. Compilation and its errors still happen first. Patterns containing escapes or character classes, and non-ASCII endings, retain the general path. The ASCII restriction matters: regexp treats malformed UTF-8 path bytes as replacement runes, so a byte suffix check on a Unicode ending could incorrectly reject an existing match. Carets are also treated as a boundary because the existing compiler can interpret them as regexp anchors. Pattern exclusion and parent matching remain unchanged.
