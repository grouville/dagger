The engine can reuse immutable core field definitions across private clients while preserving the complete collection pipeline. The experiment reduces test-edited listing allocation by about 524 MB per pair and CPU in all four pairs. Complete elapsed time improves only modestly: **6.32 → 6.19 seconds**. This is a review candidate, not the three-second solution.

Each getter still gets its own client, root, mutable class state and execution. Discovery, initializers, module ownership, source/configuration reads, selection, actual execution, errors, cancellation, telemetry and cleanup follow their existing paths. Four lossless profiles retain **800 authored getter executions, 804 module evaluations, 799 discovery hits and 1,415 SDK requests** in both modes, without dropped events or open operations. No new collection form is required.

The repeated work is schema metadata construction. After installing a private core API view, the candidate explicitly prepares a lazy snapshot of its field definitions. Class forks inherit that immutable snapshot. A field installation or extension invalidates the writing branch's snapshot; another view uses ordinary construction. Each client still constructs its schema header and references, and public Class.TypeDefinition callers still receive fresh field metadata. Arbitrary wrappers continue through their own definition providers: a negative control proves that omitting this guard loses a wrapper's description.

This depends on the [copy-on-write class storage](NATIVE_CLASS_FORK_COW.md) and its [separate history-isolation fix](PR_CLASS_FORK_HISTORY_ISOLATION.md). It does not share live client state or cache complete schemas across clients. The explicit opt-in requires stable field, type and directive providers. Mutating a published FieldSpec after opting in is unsupported; this is deliberately restricted to the engine's fully installed private core view. New modules and arbitrary custom providers are not automatically frozen. The parent lock ordering remains, and first construction uses sync.OnceValue. There is no global metadata lookup lock or unbounded process cache. A view retains its descriptors for its existing lifetime.

Schema view filtering also needed an ownership fix: it used to remove hidden directives directly from definitions supplied by a provider. A retained-definition regression fails in both view orders under the original code. The candidate copies only nodes whose directives change and rebinds schema references to the filtered nodes. This protects shared snapshots and custom providers; it is not evidence of an observed production miss. The full production diff is 174 insertions and 17 deletions across three files, plus 221 test/benchmark lines. Most of the extra code protects ownership rather than adding another fast path.
