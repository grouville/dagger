# Unselected Go discovery experiments

The archive preserves three experiments on the real Dagger Go collection listing. They do not establish the three-second goal. No PR is opened.

| Experiment | Ordinary-source median | Test-file-edit median | Decision |
| --- | ---: | ---: | --- |
| Share module source-marker results | 6.00 → 5.80 s | 11.86 → 11.74 s | Unselected; modest source-only gain, mixed test edits |
| Replace private insertion sorts with experimental native sort | 6.12 → 6.31 s | Not run | Unselected; new language API without demonstrated total-command gain |
| Share compiled function argument metadata | 5.96 → 6.25 s | 11.74 → 11.69 s | Unselected; component savings do not carry through to latency |

These are separate cohorts. Each comparison uses the same engine and CLI in both arms. Fresh CLI processes, real source edits, normal telemetry and GC, successful cleanup and final log flush are included. All 64 commands succeed and return correct ordered rows, including excluded initialization commands. Timings exclude profiling and concurrent builds/tests.

The argument-metadata study corrects an earlier protocol limitation: both arms complete the initialization test's removal before measured source-only pairs. The other studies retain the first measured arm's removal cost and must not describe that first pair as equivalent ordinary-source-only work. Every attempt remains included.

The metadata study changes only `pkg/dang/ast_declarations.go` in its standalone patch. It shares immutable names/default-expression definitions by inferred function signature, with current closures and receiver state per evaluation. Its full pristine-upstream interpreter race suite, development interpreter/SDK race suites and seven module/library checks pass. The component's method-heavy 800-package fixture improves about 1.73 → 1.19 s and 1.78 → 1.06 GB, but real test-edit allocation only moves 16.59 → 16.32 GB. Host CPU pressure reaches 22.1% in that cohort and 37.1% in the ordinary-source cohort.

Both metadata captures are lossless: 270,126 / 270,138 events, zero drops/open operations. They retain 804 module evaluations, 2,293 SDK requests, 800 getters and one test discovery execution plus 799 hits. The candidate profile still places 2.48 s in session lifecycle waits and 1.81 s in result encoding on its 11.41-second main-query critical path. Those are diagnostic intervals, not demonstrated removable savings. Sampled CPU under function-value creation falls below the report threshold, but nested object-body evaluation stays about 4 CPU-seconds. The next experiment must share a larger part of call/receiver preparation.

`assessment.json` summarizes the metadata cohorts and restoration. `manifest.json` records each archived member's size and SHA-256; `archive.json` records the verified archive identity. Sources, independent patches, drivers, failures/corrections, complete outputs, pressure/counters, tests, activation/restoration records, CPU profiles and wcprof chunks are retained. Binaries, volumes, generated bytecode and duplicate uncompressed wcprof streams are excluded. The Go module sources for all comparison arms are included under `module-source/`.

For each capture, decompress its numbered `chunk-*.ndjson.gz` files in order. Each has a header followed by newly drained events. Use the final header/string table, concatenate all event lines, and update `event_count` to recover the combined recording. The capture driver documents and checks this process.
